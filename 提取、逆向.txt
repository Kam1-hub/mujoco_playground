  # G1 Pipeline 提取与逆向映射说明

  ## 文档 1：正向提取说明（从 MuJoCo Playground 到独立 Template）

  ### 1. 提取目标

  从 MuJoCo Playground 多机器人仓库中提取**宇树 G1 人形机器人的完整训练 pipeline**，使其：
  - 完全独立，不依赖原仓库
  - 保留原仓库的工程化文件管理结构
  - 剔除所有无关内容（其他 8 个机器人、manipulation、dm_control_suite）
  - 可直接运行（从环境定义到训练脚本）

  ### 2. 提取策略

  #### 2.1 核心原则

  **包名重命名**：`mujoco_playground` → `g1_env`
  - 原因：避免与原仓库冲突，明确表达这是 G1 专用环境
  - 影响：所有导入路径需要全局替换

  **选择性复制**：
  - ✅ 复制：G1 相关的所有文件
  - ✅ 复制：通用基础设施（mjx_env, gait, reward, wrapper）
  - ❌ 删除：其他机器人（Apollo, Barkour, Berkeley Humanoid, Go1, H1, OP3, Spot, T1）
  - ❌ 删除：manipulation 任务
  - ❌ 删除：dm_control_suite 任务

  **裁剪注册系统**：
  - 原仓库的注册系统支持 3 个任务域（locomotion, manipulation, dm_control_suite）
  - Template 仅保留 locomotion，且仅注册 G1 的 2 个环境

  #### 2.2 文件映射关系

  **第一类：完整复制的基础设施文件（5个）**

  这些文件从原仓库复制后，仅修改了导入路径（mujoco_playground → g1_env）：

  ### 3. 关键修改点总结

  #### 3.1 导入路径替换（全局）

  所有文件中的导入路径需要替换：
  ```python
  # 修改前
  import mujoco_playground
  from mujoco_playground import registry
  from mujoco_playground._src import mjx_env
  from mujoco_playground.config import locomotion_params

  # 修改后
  import g1_env
  from g1_env import registry
  from g1_env._src import mjx_env
  from g1_env.config import locomotion_params

  3.2 注册系统裁剪

  registry.py 的变化：
  # 原仓库（支持 3 个任务域）
  from mujoco_playground._src import dm_control_suite
  from mujoco_playground._src import locomotion
  from mujoco_playground._src import manipulation

  ALL_ENVS = (
      dm_control_suite.ALL_ENVS +
      locomotion.ALL_ENVS +
      manipulation.ALL_ENVS
  )

  # Template（仅支持 locomotion）
  from g1_env._src import locomotion

  ALL_ENVS = locomotion.ALL_ENVS

  locomotion/init.py 的变化：
  # 原仓库（9 个机器人）
  from mujoco_playground._src.locomotion import apollo
  from mujoco_playground._src.locomotion import barkour
  from mujoco_playground._src.locomotion import berkeley_humanoid
  from mujoco_playground._src.locomotion.g1 import joystick as g1_joystick
  from mujoco_playground._src.locomotion import go1
  from mujoco_playground._src.locomotion import h1
  from mujoco_playground._src.locomotion import op3
  from mujoco_playground._src.locomotion import spot
  from mujoco_playground._src.locomotion import t1

  _envs = {
      "ApolloWalk": ...,
      "BarkourRun": ...,
      "BerkeleyHumanoidWalk": ...,
      "G1JoystickFlatTerrain": ...,
      "G1JoystickRoughTerrain": ...,
      "Go1Run": ...,
      "H1Walk": ...,
      "OP3Walk": ...,
      "SpotRun": ...,
      "T1Walk": ...,
  }

  # Template（仅 G1）
  from g1_env._src.locomotion.g1 import joystick as g1_joystick
  from g1_env._src.locomotion.g1 import randomize as g1_randomize

  _envs = {
      "G1JoystickFlatTerrain": functools.partial(
          g1_joystick.Joystick, task="flat_terrain"
      ),
      "G1JoystickRoughTerrain": functools.partial(
          g1_joystick.Joystick, task="rough_terrain"
      ),
  }

  3.3 训练配置裁剪

  locomotion_params.py 的变化：
  # 原仓库（支持所有机器人）
  def brax_ppo_config(env_name: str, impl: Optional[str] = None):
      # ... 默认配置 ...

      if env_name == "ApolloWalk":
          # Apollo 配置
      elif env_name == "BarkourRun":
          # Barkour 配置
      # ... 其他机器人 ...
      elif env_name in ("G1JoystickFlatTerrain", "G1JoystickRoughTerrain"):
          # G1 配置
      else:
          raise ValueError(f"Unsupported env: {env_name}")

  # Template（仅 G1）
  def brax_ppo_config(env_name: str, impl: Optional[str] = None):
      # ... 默认配置 ...

      if env_name in ("G1JoystickFlatTerrain", "G1JoystickRoughTerrain"):
          rl_config.num_timesteps = 200_000_000
          rl_config.num_evals = 20
          rl_config.clipping_epsilon = 0.2
          rl_config.entropy_cost = 0.005
          rl_config.network_factory = config_dict.create(
              policy_hidden_layer_sizes=(512, 256, 128),
              value_hidden_layer_sizes=(512, 256, 128),
              policy_obs_key="state",
              value_obs_key="privileged_state",
          )
      else:
          raise ValueError(
              f"Unsupported env: {env_name}. "
              "Only G1 environments are supported in this template."
          )

  文档 2：逆向映射说明（从 Template 回到 MuJoCo Playground）

  1. 逆向映射的目的

  当你学习完 Template 中的 G1 pipeline 后，回到 MuJoCo Playground 原仓库时，需要理解：
  - Template 中的每个文件对应原仓库的哪个文件
  - Template 中被裁剪的内容在原仓库中是什么样子
  - 如何在原仓库中找到其他机器人的实现

  2. 包名逆向映射

  核心规则：g1_env → mujoco_playground

  在 Template 中看到的所有 g1_env 导入，在原仓库中都是 mujoco_playground：

  import g1_env
  from g1_env import registry
  from g1_env._src import mjx_env
  from g1_env._src.locomotion.g1 import joystick

  # 原仓库中
  import mujoco_playground
  from mujoco_playground import registry
  from mujoco_playground._src import mjx_env

  7.3 理解原仓库的完整架构

  原仓库的三层架构：

  1. 注册层（registry.py）
     ├── 聚合所有任务域的环境
     └── 提供统一的加载接口

  2. 任务域层（locomotion, manipulation, dm_control_suite）
     ├── 每个任务域有独立的 __init__.py
     ├── 注册该域下的所有环境
     └── 提供域特定的配置

  3. 机器人层（g1, h1, spot, etc.）
     ├── 每个机器人有独立的目录
     ├── 包含环境定义、常量、任务
     └── 包含 XML 模型文件

  Template 简化为两层：

  1. 注册层（registry.py）
     └── 直接调用 locomotion 模块

  2. 机器人层（g1）
     ├── 仅包含 G1
     └── 完整的 G1 实现

  8. 总结

  从 Template 到原仓库的映射规则：

  1. 包名：g1_env → mujoco_playground
  2. 路径：g1_env/_src/ → mujoco_playground/_src/
  3. 环境数量：2 个 → 30+ 个
  4. 任务域：1 个（locomotion） → 3 个（locomotion + manipulation + dm_control_suite）
  5. 机器人：1 个（G1） → 9 个（Apollo, Barkour, Berkeley Humanoid, G1, Go1, H1, OP3, Spot, T1）

  学习路径建议：

  1. 先在 Template 中深入学习 G1 的完整实现
  2. 理解 MJX 环境的基本结构（mjx_env.py）
  3. 理解注册系统的工作原理（registry.py, locomotion/init.py）
  4. 回到原仓库，对比其他机器人的实现
  5. 探索 manipulation 和 dm_control_suite 任务域
