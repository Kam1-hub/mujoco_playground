### 26.1 `g1_env/_src/locomotion/g1/g1_constants.py`

优先级：最高。

原因：

`mjx_env.py` 本身只提供通用路径、State、step、sensor 查询工具；但 G1 的具体 XML 路径、传感器命名前缀、脚/手 site 名称、关节范围、root body 名称等，不在 `mjx_env.py` 里，而是在 `g1_constants.py` 里。文件结构说明它负责 G1 常量定义，包括资源路径、XML 文件路径、脚部/手部位置、几何体 ID、传感器名称和 29 个执行器的关节范围限制。

你需要确认：

```text
1. ROOT_PATH 指向哪里
   → 决定 base.py::get_assets() 从哪里加载 g1_env/_src/locomotion/g1/xmls。

2. task_to_xml(task) 如何映射
   → task="flat_terrain" 到底对应哪个 XML
   → task="rough_terrain" 到底对应哪个 XML

3. ROOT_BODY 是什么
   → joystick.py 里用 consts.ROOT_BODY 找 torso/root body
   → 会影响 torso mass、base 相关 reward、姿态判断

4. FEET_SITES / HAND_SITES / FEET_GEOMS 的具体名字
   → joystick.py::_post_init() 用它们查 site/geom id
   → 会影响 feet height、feet velocity、contact 判断

5. 传感器前缀常量
   → GRAVITY_SENSOR
   → GLOBAL_LINVEL_SENSOR
   → GLOBAL_ANGVEL_SENSOR
   → LOCAL_LINVEL_SENSOR
   → ACCELEROMETER_SENSOR
   → GYRO_SENSOR

6. RESTRICTED_JOINT_RANGE 的 shape 和数值
   → base.py 中 restricted_joint_range=True 时会覆盖 mj_model.jnt_range[1:] 和 actuator_ctrlrange
```

为什么它接在 `mjx_env.py` 后面看：

```text
mjx_env.get_sensor_data(model, data, sensor_name)
→ base.py.get_gyro(data, frame)
→ sensor_name = f"{consts.GYRO_SENSOR}_{frame}"
→ g1_constants.py 决定真正 sensor 名字
→ XML 里必须存在这个 sensor
```

这一层是 “Python 任务代码” 和 “XML 命名系统” 的桥。你如果不看它，后面读 XML 时很难知道哪些名字是被代码硬编码依赖的。

### 26.2 `g1_env/_src/locomotion/g1/xmls/sensor.xml`

优先级：最高。

原因：

当前 `mjx_env.py` 的 `get_sensor_data()` 是按 sensor 名称从 `data.sensordata` 切片；`base.py` 的 `get_gyro/get_gravity/get_local_linvel/...` 都依赖这些 sensor；`joystick.py` 的 observation、reward、termination 又依赖这些 wrapper。因此 `sensor.xml` 是 observation / reward / termination 的底层数据来源。

文件结构说明 `sensor.xml` 定义了 IMU、接触力传感器、线速度传感器等。

你需要确认：

```text
1. gyro / accelerometer sensor 名称
   → 是否匹配 base.py.get_gyro(data, "pelvis")
   → 是否匹配 base.py.get_accelerometer(data, "pelvis")

2. gravity sensor 名称
   → 是否有 torso / pelvis 两套
   → joystick.py::_get_termination 用 torso gravity
   → joystick.py::_get_obs 用 pelvis gravity

3. local/global linvel sensor 名称
   → tracking_lin_vel 用 local_linvel_pelvis
   → feet_slip / feet_phase mask 用 global_linvel_pelvis

4. global_angvel sensor 名称
   → orientation / ang_vel_xy / privileged_state 相关

5. foot force sensor 名称
   → joystick.py::_cost_contact_force 读取 left_foot_force / right_foot_force

6. contact found sensor 名称
   → left_foot_floor_found
   → right_foot_floor_found
   → right_foot_left_foot_found
   → left_foot_right_shin_found
   → right_foot_left_shin_found
   → left_hand_left_thigh_found
   → right_hand_right_thigh_found
```

重点不是只看它“有哪些 sensor”，而是建立这条链：

```text
XML sensor name
→ mj_model.sensor(sensor_name).id
→ sensor_adr / sensor_dim
→ data.sensordata slice
→ base.py sensor wrapper
→ joystick.py obs/reward/termination
```

如果 sensor 名字不匹配，环境不是 reward 错一点，而是会在初始化或 step 时直接失败。

### 26.3 `g1_env/_src/locomotion/g1/xmls/g1_mjx_feetonly.xml`

优先级：最高。

原因：

这是 G1 主模型文件。文件结构说明它包含 29 个关节，以及身体、几何体、执行器定义。

你需要确认：

```text
1. freejoint 是否是第一个 joint
   → joystick.py 默认 qpos[7:] 是关节
   → joystick.py 默认 qvel[6:] 是关节速度
   → base.py restricted_joint_range 跳过 jnt_range[1:]
   → mjx_env.qpos_width/qvel_width 也说明 freejoint qpos=7, qvel=6

2. actuator 数量是否为 29
   → G1Env.action_size = mjx_model.nu
   → joystick.py 中 action / last_act / actuator_force 都按 29 维处理

3. actuator 类型
   → position actuator / motor actuator / general actuator？
   → 这决定 joystick.py 中 motor_targets 写入 ctrl 后到底是什么含义
   → 当前 Python 代码只能确认 ctrl = motor_targets，不能确认 actuator 如何解释 ctrl

4. actuator ctrlrange
   → 是否和 joint range 对齐
   → restricted_joint_range=True 时会被 consts.RESTRICTED_JOINT_RANGE 覆盖

5. keyframe knees_bent
   → joystick.py::_post_init() 用它作为 init_q 和 default_pose
   → joystick.py::reset() 初始 qpos 来自它
   → joystick.py::step() 的 action 中心也是它

6. body/site/geom 名称
   → imu_in_torso
   → imu_in_pelvis
   → left_foot / right_foot
   → left_shin / right_shin
   → left_thigh / right_thigh
   → left_hand_collision / right_hand_collision

7. collision geom 设置
   → “feetonly” 暗示碰撞模型可能被简化
   → 需要确认哪些身体部位有 collision geom
```

这一步是为了回答一个核心问题：

```text
policy 输出 29 维 action
→ joystick.py 转成 29 维 motor_targets
→ mjx_env.step 写入 data.ctrl
→ XML actuator 如何把 ctrl 变成关节驱动？
```

这个问题必须看 XML，不能只靠 Python 文件判断。

### 26.4 `g1_env/_src/locomotion/g1/xmls/scene_mjx_feetonly_flat_terrain.xml` 和 `scene_mjx_feetonly_rough_terrain.xml`

```text

  - 包含 g1_mjx_feetonly.xml
  - 平面地板

scene_mjx_feetonly_rough_terrain.xml:
  - 高度场地形
  - 岩石纹理
```



你需要确认：

```text
1. flat terrain 的 floor geom 如何定义
   → geom name 是否为 "floor"
   → joystick.py::_post_init() 依赖 self._mj_model.geom("floor").id

2. rough terrain 是否使用 hfield
   → 是否引用 assets/hfield.png
   → 是否使用 rocky_texture.png

3. 两个 scene 是否都 include sensor.xml
   → 如果 rough terrain 忘记 include sensor.xml，Python sensor 读取会失败

   → floor geom 名称是否一致
```

这一步可以解释：

```text
同一个 Joystick 类
→ 为什么能得到 flat terrain 和 rough terrain 两个环境？
```

答案大概率是：

```text
task_to_xml(task)
→ 选择不同 scene XML
→ scene XML 中 terrain 不同
→ Python 任务逻辑基本共用
```

### 26.5 `g1_env/_src/locomotion/g1/randomize.py`

优先级：高。

原因：

`mjx_env.py` 没有实现 domain randomization。前面 `locomotion.__init__.py` 中 `_randomizer` 把两个环境都映射到 `g1_randomize.domain_randomize`。文件结构说明 `randomize.py` 中的 `domain_randomize` 会随机化摩擦力、关节摩擦损失、电枢、质量、初始位置等。

你需要确认：

```text
1. domain_randomize 的函数签名
   → 是否是 Callable[[mjx.Model, jax.Array], Tuple[mjx.Model, mjx.Model]]
   → 是否和 registry.py / locomotion.__init__.py 中的类型一致

2. 它随机化哪些字段
   → geom_friction？
   → dof_frictionloss？
   → dof_armature？
   → body_mass？
   → qpos0 / body_pos？

3. 返回值的两个 mjx.Model 分别是什么
   → 这是前面 registry 类型中最不清楚的一点
   → 需要源码确认，不能猜

4. 是否 batch randomization
   → 是否为 num_envs 生成不同 model 参数
   → 是否和 Brax PPO 的 domain_randomization API 对齐

5. 是否覆盖 flat / rough 两个环境
   → 当前 registry 中两个环境都用同一个 randomizer
   → 需要确认它是否依赖 terrain 类型
```

数据流要这样追：

```text
train_jax_ppo.py
→ registry.get_domain_randomizer(env_name)
→ locomotion.get_domain_randomizer(env_name)
→ randomize.domain_randomize
→ Brax PPO / wrapper 接收 randomization_fn
```

注意：只看 `randomize.py` 还不够。还要看训练脚本是否真的调用并传入它。否则会出现：

```text

但 training script 没有接入
→ 实际训练没有 domain randomization
```

### 26.8 `g1_env/_src/wrapper.py`

优先级：高。

原因：

`mjx_env.py` 定义的是原始环境接口：

```text
reset(rng) -> State
step(state, action) -> State
obs 可以是 dict
State 里有 data / obs / reward / done / metrics / info
```

但 Brax PPO 通常需要特定的 env wrapper、batching、episode truncation、domain randomization 接口、metrics 格式。文件结构说明 `wrapper.py` 是 Brax 环境包装器，包含 `Wrapper` 和 `wrap_for_brax_training`。

你需要确认：

```text
1. wrap_for_brax_training 做了什么
   → 是否 vmapped reset / step
   → 是否处理 num_envs
   → 是否处理 episode_length
   → 是否自动 reset done env
   → 是否处理 action repeat

2. obs dict 如何传给 Brax PPO
   → actor 用 obs["state"]？
   → critic 是否能拿 obs["privileged_state"]？
   → privileged_state 是否被保留或丢弃？

3. reward / done 格式如何包装
   → 是否转换成 Brax training 期望的 State
   → metrics 是否被保留

4. domain randomization 如何接入
   → 是否接收 randomization_fn
   → 是否把 mjx.Model batch 化
   → 是否调用 randomize.domain_randomize

5. observation_size / action_size 是否用于网络初始化
```

这一步非常关键，因为 `mjx_env.py` 只是定义了“环境原生接口”，而 `wrapper.py` 决定它如何被 Brax PPO 消费。

核心数据流：

```text
Joystick / MjxEnv 原生接口
→ wrapper.wrap_for_brax_training(...)
→ Brax PPO 可接受的 env 接口
→ train_jax_ppo.py
```

【建议阅读顺序】

如果你的目标是继续理解 `mjx_env.py` 之后的 pipeline，我建议按这个顺序读：

```text
1. g1_constants.py
   → 搞清楚 XML 路径、sensor 名称、关节范围、site/geom 常量

2. sensor.xml
   → 搞清楚 observation/reward/termination 的传感器底层来源

3. g1_mjx_feetonly.xml
   → 搞清楚 29 关节、actuator、keyframe knees_bent、body/site/geom

4. flat / rough scene XML
   → 搞清楚两个任务环境的地形差异到底在哪里

5. gait.py
   → 搞清楚 feet_phase reward 的步态相位先验

6. randomize.py
   → 搞清楚 domain randomization 到底随机化哪些物理参数

7. wrapper.py
   → 搞清楚 MJX env 如何接 Brax PPO

8. locomotion_params.py
   → 搞清楚 PPO 训练超参数、网络结构、num_envs 等

9. train_jax_ppo.py
   → 搞清楚 JAX/Brax 训练主流程

10. wrapper_torch.py
    → 搞清楚 JAX↔Torch 转换和 RSL-RL VecEnv

11. train_rsl_rl.py
    → 搞清楚 RSL-RL 训练主流程
```

最核心的继续阅读路线是：

```text
mjx_env.py
→ base.py
→ g1_constants.py
→ XML/sensor.xml
→ joystick.py
→ randomize.py
→ wrapper.py
→ locomotion_params.py
→ train_jax_ppo.py
```

如果只关心“环境本身怎么跑”，读到 `joystick.py + base.py + mjx_env.py + g1_constants.py + XML` 基本够了。

如果关心“训练 pipeline 怎么跑”，必须继续读：

```text
wrapper.py
locomotion_params.py
train_jax_ppo.py
```

如果关心 “RSL-RL / PyTorch 怎么接 MJX”，必须继续读：

```text
wrapper_torch.py
train_rsl_rl.py
```
