【1. 这段代码在 pipeline 中的位置】

`train_jax_ppo.py` 属于 **PPO 训练入口层 / Brax PPO 训练后端接入层 / JAX 训练脚本层**。

它不是环境本体，不实现 G1 的 `reset()` / `step()` / reward / observation，也不直接写 MuJoCo 动力学。它的职责是把前面已经定义好的环境、配置、wrapper、PPO 算法、日志、checkpoint、eval、视频录制串成一条完整训练 pipeline。源码开头也明确写了：`Train a PPO agent using JAX on the specified environment.` 

它在整个工程中的位置是：

```text id="1n8py6"
命令行 / 脚本入口 train-g1-jax
→ learning/train_jax_ppo.py
→ registry.get_default_config(env_name)
→ registry.load(env_name, config, config_overrides)
→ Joystick / G1Env / MjxEnv
→ wrapper.wrap_for_brax_training
→ brax.training.agents.ppo.train
→ checkpoint / eval / inference / video
```

更完整地放入你目前读过的文件链条中：

```text id="b2qzry"
train_jax_ppo.py
→ g1_env.registry
→ g1_env._src.locomotion.__init__
→ g1_joystick.Joystick
→ g1_base.G1Env
→ mjx_env.MjxEnv
→ mujoco.MjModel / mjx.Model
→ Brax PPO
```

所以这个文件是目前 G1 RL pipeline 中第一个真正把“环境”交给“训练算法”的文件。

---

【2. 核心作用】

这个文件的核心作用是：

```text id="opg0v5"
读取命令行参数
→ 加载 G1 环境配置
→ 加载 PPO 训练配置
→ 根据参数覆盖 config
→ 创建训练环境 / eval 环境 / inference 环境
→ 构造 Brax PPO train_fn
→ 启动训练或加载 checkpoint
→ 保存 checkpoint 和日志
→ 训练后跑 deterministic policy
→ 渲染 rollout 视频
```

它接收的主要输入：

```text id="fb97s8"
1. 命令行 flags
   - env_name
   - impl
   - playground_config_overrides
   - vision
   - load_checkpoint_path
   - play_only
   - domain_randomization
   - seed
   - PPO 参数覆盖项
   - logging 参数
   - video 数量

2. 环境注册表
   - registry.ALL_ENVS
   - registry.get_default_config
   - registry.load
   - registry.get_domain_randomizer

3. PPO 默认配置
   - locomotion_params.brax_ppo_config(env_name, impl)

4. G1 环境对象
   - Joystick / G1Env / MjxEnv
```

它产生的主要输出：

```text id="dl838u"
1. 训练好的 PPO policy 参数
2. checkpoint 文件夹
3. config.json
4. TensorBoard / WandB 日志
5. eval metrics
6. rollout 视频 mp4
7. inference function
```

它直接调用的关键模块：

```text id="p1eysf"
registry
wrapper.wrap_for_brax_training
locomotion_params.brax_ppo_config
brax.training.agents.ppo.train
ppo_networks.make_ppo_networks
ppo_networks_vision.make_ppo_networks_vision
jax.jit / jax.vmap / jax.lax.scan
infer_env.render
mediapy.write_video
```

它对训练的实际影响很大，因为它决定：

```text id="sii3r0"
1. 使用哪个环境
2. 使用 JAX 还是 Warp MJX backend
3. PPO 总步数、num_envs、batch size、learning rate 等
4. actor / critic 分别读 obs 的哪个 key
5. 是否启用 domain randomization
6. 是否启用 vision input
7. 是否恢复 checkpoint
8. eval 和 inference 如何跑
9. 视频录制如何生成
```

【3. 顶层环境变量与运行时设置】

文件开头设置了几个运行时环境变量：

```python id="p72veb"
xla_flags += " --xla_gpu_triton_gemm_any=True"
os.environ["XLA_FLAGS"] = xla_flags
os.environ["XLA_PYTHON_CLIENT_PREALLOCATE"] = "false"
os.environ["MUJOCO_GL"] = "egl"
```

这些属于 **JAX/MuJoCo 运行时设置**，不是 RL 算法逻辑。

含义：

```text id="m31j08"
XLA_FLAGS:
  启用 XLA GPU Triton GEMM 相关选项。

XLA_PYTHON_CLIENT_PREALLOCATE=false:
  禁止 JAX 启动时预分配大块 GPU 显存。

MUJOCO_GL=egl:
  MuJoCo 渲染使用 EGL 后端，适合 headless / Linux GPU 环境。
```

对你的 WSL2/MJX pipeline 有直接意义：

```text id="tj3wzt"
训练阶段：
  XLA_PYTHON_CLIENT_PREALLOCATE=false 可减少 JAX 贪婪占显存问题。

渲染阶段：
  MUJOCO_GL=egl 影响 mujoco.Renderer 能否正常工作。
```

潜在工程点：

```text id="i3bcsw"
这些环境变量是在 Python import 后设置的。
如果某些库在此之前已经读取了环境变量，可能不完全生效。
但当前文件在训练主体前设置，通常是为了尽早影响 JAX/MuJoCo。
```

【4. flags：命令行参数层】

这个文件定义了大量 `absl.flags`。这些 flags 分为几类。

---

### 4.1 环境选择相关

```python id="q66r8c"
_ENV_NAME = "G1JoystickFlatTerrain"
_IMPL = enum("jax", "warp")
_PLAYGROUND_CONFIG_OVERRIDES = string
_VISION = bool
_DOMAIN_RANDOMIZATION = bool
```

作用：

```text id="z4mchx"
env_name:
  决定加载 G1JoystickFlatTerrain 还是 G1JoystickRoughTerrain。

impl:
  传给环境 config override，决定 MJX model 使用 jax 还是 warp 实现。

playground_config_overrides:
  JSON 字符串，用于额外覆盖环境 config。

vision:
  是否使用 vision input，同时影响 network_factory 和 env config。

domain_randomization:
  是否把 registry.get_domain_randomizer(env_name) 传给 PPO train。
```

数据流：

```text id="gsc79i"
--env_name
→ registry.get_default_config
→ registry.load

--impl
→ env_cfg_overrides["impl"]
→ G1Env
→ mjx.put_model(..., impl=config.impl)

--domain_randomization
→ registry.get_domain_randomizer
→ training_params["randomization_fn"]
→ ppo.train
```

注意：`impl` 的默认 flag 是 `"jax"`，而 `joystick.default_config()` 里默认 `impl="warp"`。本脚本会始终构造：

```python id="6d8jky"
env_cfg_overrides = {"impl": _IMPL.value}
```

所以如果你用这个训练脚本且不显式传 `--impl=warp`，实际环境会被覆盖成 `impl="jax"`，而不是使用 `joystick.default_config()` 里的 `"warp"`。这是一个关键点。

### 4.2 checkpoint / play only / logging 相关

```python id="x5ylqm"
_LOAD_CHECKPOINT_PATH
_SUFFIX
_PLAY_ONLY
_USE_WANDB
_USE_TB
_LOGDIR
```

作用：

```text id="66lcs7"
load_checkpoint_path:
  从已有 checkpoint 恢复。

play_only:
  设置 ppo_params.num_timesteps = 0，只跑加载/推理/渲染流程。

suffix:
  加到实验名后面。

use_wandb:
  训练时用 WandB 记录日志。

use_tb:
  训练时用 TensorBoard 记录日志。

logdir:
  指定日志根目录。
```

需要注意：

```text id="c0m82l"
play_only=True 不会跳过 train_fn 调用。
它只是把 num_timesteps 设置为 0，然后仍然调用 ppo.train。
如果没有提供 checkpoint，可能得到未训练或不符合预期的参数。
```

这不是凭空推断：代码中 `if _PLAY_ONLY.present: ppo_params.num_timesteps = 0`，但后面仍然执行 `make_inference_fn, params, _ = train_fn(...)`。

### 4.3 PPO 训练参数覆盖项

这部分包括：

```text id="qbcxsg"
num_timesteps
num_evals
reward_scaling
episode_length
normalize_observations
action_repeat
unroll_length
num_minibatches
num_updates_per_batch
discounting
learning_rate
entropy_cost
num_envs
num_eval_envs
batch_size
max_grad_norm
clipping_epsilon
policy_hidden_layer_sizes
value_hidden_layer_sizes
policy_obs_key
value_obs_key
```

这些 flags 的作用是覆盖 `locomotion_params.brax_ppo_config()` 返回的默认 PPO 配置。

但是要注意一个非常重要的行为：

```python id="rdk1my"
if _NUM_TIMESTEPS.present:
    ppo_params.num_timesteps = _NUM_TIMESTEPS.value
```

很多参数都使用 `.present` 判断。这通常意味着：

```text id="2q13ye"
只有用户在命令行显式传了该 flag，才覆盖 locomotion_params.py 中的默认配置。
```

因此，虽然代码里 `_NUM_ENVS` flag 默认写的是 `1024`，但如果用户没有显式传 `--num_envs`，最终很可能仍然使用 `locomotion_params.brax_ppo_config()` 里的默认 `num_envs`。根据你提供的 filemap，`locomotion_params.py` 中 Brax PPO 默认 `num_envs=8192`，`num_timesteps=200M`，网络结构是 Policy `(512,256,128)`、Value `(512,256,128)`。

所以不能简单说：

```text id="u7b73f"
这个脚本默认 num_envs=1024
```

更准确是：

```text id="w9fyyr"
flag 定义中的默认值是 1024；
但代码只在 _NUM_ENVS.present 时覆盖 ppo_params；
实际默认训练值要看 locomotion_params.brax_ppo_config。
```

这是读这个文件时最容易误解的地方之一。

### 4.4 actor / critic observation key

```python id="pc78th"
_POLICY_OBS_KEY = "state"
_VALUE_OBS_KEY = "state"
```

这两个参数会覆盖：

```python id="bhdai6"
ppo_params.network_factory.policy_obs_key
ppo_params.network_factory.value_obs_key
```

它们决定 PPO 网络从 observation dict 中取哪个 key。

结合 `joystick.py`：

```python id="kulrl7"
obs = {
    "state": state,
    "privileged_state": privileged_state,
}
```

所以有几种可能：

```text id="vd4458"
policy_obs_key="state", value_obs_key="state":
  actor 和 critic 都用普通 state。

policy_obs_key="state", value_obs_key="privileged_state":
  actor 用部署可用 state；
  critic 用 privileged_state；
  这就是 asymmetric actor-critic / privileged critic 路线。

policy_obs_key="privileged_state":
  actor 也用 privileged_state；
  这通常会造成训练/部署不一致，除非只做 teacher 或 sim-only policy。
```

当前脚本的 flag 默认值是 `"state"`，但是否真正覆盖同样取决于 `.present`。因此实际 actor/critic obs key 要看：

```text id="p5m9um"
1. locomotion_params.brax_ppo_config 里的 network_factory 默认值
2. 命令行是否显式传了 --policy_obs_key / --value_obs_key
```

仅凭这个文件不能断言默认 critic 是否使用 `privileged_state`。

【5. `get_rl_config(env_name)`：PPO config 选择入口】

```python id="e4y0p7"
def get_rl_config(env_name: str) -> config_dict.ConfigDict:
  if env_name in g1_env.locomotion._envs:
    return locomotion_params.brax_ppo_config(env_name, _IMPL.value)

  raise ValueError(...)
```

这个函数属于 **训练超参数选择层**。

输入：

```text id="qr0jmf"
env_name
```

输出：

```text id="f4j9ld"
ppo_params: ConfigDict
```

它做的事情：

```text id="x9vob8"
检查 env_name 是否在 g1_env.locomotion._envs 中
→ 如果存在，调用 locomotion_params.brax_ppo_config(env_name, impl)
→ 返回 Brax PPO 配置
```

这里有一个值得注意的工程点：

```text id="hieluw"
它直接访问 g1_env.locomotion._envs 这个内部变量。
```

更规范的方式本来可以是：

```text id="sv8fe6"
registry.ALL_ENVS
```

当前代码用的是内部 `_envs`，这会让训练脚本和 locomotion 内部实现耦合更紧。如果以后 registry 封装方式改变，这里可能受影响。

数据流：

```text id="wswp4e"
_ENV_NAME.value
→ get_rl_config(env_name)
→ locomotion_params.brax_ppo_config(env_name, impl)
→ ppo_params
→ ppo.train(**training_params)
```

【6. `rscope_fn(...)`：rscope rollout 回调】

```python id="37gcwg"
def rscope_fn(full_states, obs, rew, done):
```

这个函数用于 rscope 可视化/rollout 保存回调，不是主训练必需路径。

它假设输入 shape 是：

```text id="d1wbrl"
full_states: dict, shape (unroll_length, rscope_envs, ...)
obs: nd.array 或 dict obs
rew: shape (unroll_length, rscope_envs)
done: shape (unroll_length, rscope_envs)
```

它做的事：

```text id="1nkn6f"
done_mask = cumsum(done, axis=0)
valid_rewards = rew * (done_mask == 0)
episode_rewards = sum(valid_rewards, axis=0)
print 平均 episode reward 和 std
```

含义：

```text id="r3xg0o"
只统计每个 rollout 在第一次 done 前的 reward。
done 后的 reward 不计入 episode reward。
```

这个函数只有 `_RSCOPE_ENVS.value` 非空时才会进入相关逻辑。

【8. 环境 config 加载与 PPO config 加载】

```python id="x5l5f0"
env_cfg = registry.get_default_config(_ENV_NAME.value)
ppo_params = get_rl_config(_ENV_NAME.value)
```

这一步从两个不同系统取配置：

```text id="qitz8w"
env_cfg:
```

不要混淆：

```text id="e1fiey"
env_cfg 控制环境本身怎么跑；

```

连接到前面文件：

```text id="mb1ijj"
registry.get_default_config
→ locomotion.get_default_config
→ g1_joystick.default_config
```

【9. PPO 参数覆盖逻辑】

这一大段：

```python id="q48soc"
if _NUM_TIMESTEPS.present:

if _POLICY_HIDDEN_LAYER_SIZES.present:
```

属于 **命令行覆盖 PPO config 层**。

作用：

```text id="yogyo1"
locomotion_params.py 提供默认 PPO 配置
→ 用户命令行显式传入某些 flags
→ 覆盖 ppo_params 对应字段
```

覆盖字段分为：

```text id="q2jddb"
训练规模：
  num_timesteps
  num_envs
  num_eval_envs

PPO 算法：
  discounting
  learning_rate
  entropy_cost
  clipping_epsilon
  max_grad_norm
  reward_scaling
  num_minibatches
  num_updates_per_batch
  unroll_length

环境 rollout：
  episode_length
  action_repeat
  normalize_observations

网络：
  policy_hidden_layer_sizes
  value_hidden_layer_sizes
```

```text id="exwudk"
很多 flags 有默认值，但只有 .present 时才覆盖。
```

【10. env_cfg_overrides：环境参数覆盖逻辑】

```python id="wm8gqm"
env_cfg_overrides = {"impl": _IMPL.value}
if _VISION.value:
  env_cfg_overrides["vision"] = True
  env_cfg_overrides["vision_config.nworld"] = ppo_params.num_envs
if _PLAYGROUND_CONFIG_OVERRIDES.value is not None:
  env_cfg_overrides.update(json.loads(_PLAYGROUND_CONFIG_OVERRIDES.value))
```

这部分属于 **环境 config override 层**。

它构造一个 flattened dict，然后传给：

```python id="8ozcor"
registry.load(..., config_overrides=env_cfg_overrides)
```

下游连接：

```text id="zgy2pt"
registry.load
→ locomotion.load
→ Joystick(config=config, config_overrides=...)
→ G1Env
→ MjxEnv.__init__
→ self._config.update_from_flattened_dict(config_overrides)
```

结合 `mjx_env.py`，`config_overrides` 是通过 `ConfigDict.update_from_flattened_dict()` 处理的。

这意味着 `playground_config_overrides` 应该传 JSON，例如：

```bash id="7rctc8"
--playground_config_overrides='{"noise_config.level": 0.0, "push_config.enable": false}'
```

而不是嵌套 JSON：

```json id="o4pc5f"
{
  "noise_config": {
    "level": 0.0
  }
}
```

是否支持嵌套格式取决于 `ConfigDict.update_from_flattened_dict`，但代码意图明显是 flattened override。

### 10.1 `impl` override 的实际影响

`env_cfg_overrides` 总是包含：

```python id="dw6x8q"
{"impl": _IMPL.value}
```

`G1Env.__init__()` 中使用：

```python id="e4l7a2"
self._mjx_model = mjx.put_model(self._mj_model, impl=self._config.impl)
```

所以：

```text id="wskpqn"
--impl=jax
→ config.impl = "jax"
→ mjx.put_model(..., impl="jax")

--impl=warp
→ config.impl = "warp"
→ mjx.put_model(..., impl="warp")
```

这是训练脚本控制 MJX backend 的关键路径。

### 10.2 vision override

如果：

```bash id="a90dam"

```

则：

```text id="4e74i9"
env_cfg_overrides["vision"] = True
```

【11. 创建训练环境 `env`】

```python id="ouahq1"
env = registry.load(
```

【14. checkpoint 加载逻辑】

```python id="p73p2h"
if _LOAD_CHECKPOINT_PATH.value is not None:
    ckpt_path = epath.Path(...).resolve()
    if ckpt_path.is_dir():
        latest_ckpts = list(ckpt_path.glob("*"))
        latest_ckpts = [ckpt for ckpt in latest_ckpts if ckpt.is_dir()]
        latest_ckpts.sort(key=lambda x: int(x.name))
        latest_ckpt = latest_ckpts[-1]
        restore_checkpoint_path = latest_ckpt
    else:
        restore_checkpoint_path = ckpt_path
else:
    restore_checkpoint_path = None
```

它支持两种输入：

```text id="42zq67"
1. 传入 checkpoint 根目录
   → 找该目录下名称为数字的子目录
   → 取数字最大的那个作为 latest checkpoint

2. 传入具体 checkpoint 路径
   → 直接使用
```

潜在风险：

```text id="o6rv27"
如果目录下有非数字命名的子目录：
  latest_ckpts.sort(key=lambda x: int(x.name)) 会报错。

如果目录为空：
  latest_ckpts[-1] 会报错。

如果 play_only=True 但没有 load_checkpoint_path：
  仍然会调用 train_fn，但 num_timesteps=0，推理结果可能不是你想要的已训练策略。
```

【26. empty trajectory 构造】

这段代码：

```python id="dnpi90"
empty_data = reset_states.data.__class__(
    **{k: None for k in reset_states.data.__annotations__}
)

    **{k: None for k in reset_states.__annotations__}
```


【27. rollout `step(carry, _)`】

```python id="w8sy2p"
def step(carry, _):
    state, rng = carry
    rng, act_key = jax.random.split(rng)
    act_keys = jax.random.split(act_key, _NUM_VIDEOS.value)
    act = jax.vmap(jit_inference_fn)(state.obs, act_keys)[0]
    state = wrapped_infer_env.step(state, act)
    traj_data = empty_traj.tree_replace({...})
    return (state, rng), traj_data
```

这段是训练后视频 rollout 的单步逻辑。

数据流：

```text id="pij822"
state.obs
→ jax.vmap(jit_inference_fn)(state.obs, act_keys)
→ act
→ wrapped_infer_env.step(state, act)
→ new state
→ 抽取 qpos/qvel/time/ctrl/mocap/xfrc
→ traj_data
```

注意：

```python id="fb4rx2"
act = jax.vmap(jit_inference_fn)(state.obs, act_keys)[0]
```

`inference_fn` 返回值通常是 `(action, extras)`，所以 `[0]` 取 action。

如果 obs 是 dict，`vmap` 会沿 batch 维映射整个 dict。这要求 `wrapped_infer_env.reset` 返回的 obs 已经是 batched 格式。

【28. `do_rollout`：用 `jax.lax.scan` 跑整段 episode】

```python id="mi1w9u"
@jax.jit
def do_rollout(state, rng):
    _, traj = jax.lax.scan(
        step, (state, rng), None, length=ppo_params.episode_length
    )
    return traj
```

作用：

```text id="097ev4"
用 JAX scan 一次性跑 episode_length 步 rollout；
JIT 编译整个 rollout；
返回 time-major trajectory。
```

shape 逻辑：

```text id="e60x1u"
traj_stacked 初始 shape:
  (time, nworld, ...)

然后：
  moveaxis(time, nworld)
→ (nworld, time, ...)
```

源码中也写了注释：

```text id="n5nejg"
traj_stacked has shape (time, nworld, ...), swap to (nworld, time, ...).
```

这说明后续每个视频对应一个 world / env 的整段 trajectory。

【30. 整体训练数据流】

把这个文件完整串起来，可以写成：

```text id="ygeoe4"
命令行参数

→ env_cfg = registry.get_default_config(env_name)
```

更贴近 G1 环境内部的数据流：

```text id="8xtrgd"
Brax PPO
→ wrapped env.step
→ Joystick.step
→ policy action
→ motor_targets = default_pose + action * action_scale
→ mjx_env.step(mjx_model, data, motor_targets, n_substeps)
→ _get_obs / _get_reward / _get_termination
→ State(obs, reward, done, metrics)
→ Brax PPO update
```

【33. 容易误解或需要注意的点】

### 33.1 flags 默认值不等于实际默认训练参数

这是最重要的点。

例如：

```python id="c7rteo"
_NUM_ENVS = flags.DEFINE_integer("num_envs", 1024, ...)
```

但覆盖时：

```python id="of99t5"
if _NUM_ENVS.present:
    ppo_params.num_envs = _NUM_ENVS.value
```

所以如果命令行没有显式传 `--num_envs`，实际 `ppo_params.num_envs` 来自 `locomotion_params.brax_ppo_config`，不是这里的 1024。

读这个脚本时，要以打印出来的：

```text id="h9cywy"
PPO Training Parameters
```

为最终准。

---

### 33.2 `impl` 会覆盖环境默认值

`joystick.default_config()` 默认 `impl="warp"`，但本脚本 `_IMPL` 默认 `"jax"`，并且总是放入：

```python id="q5x4je"
env_cfg_overrides = {"impl": _IMPL.value}
```

因此：

```text id="u7j3yh"
运行 train_jax_ppo.py 且不传 --impl=warp
→ 实际 impl 是 jax
```

这可能和你读 `joystick.py` 时看到的默认值不同。

---

### 33.3 domain randomization 默认关闭

虽然 `locomotion.__init__.py` 注册了 randomizer，但当前脚本只有：

```python id="6grt0t"
if _DOMAIN_RANDOMIZATION.value:
    training_params["randomization_fn"] = registry.get_domain_randomizer(...)
```

所以默认 `--domain_randomization=False` 时，不会接入 randomizer。

这意味着：

```text id="4aswcb"
存在 randomize.py
≠ 训练使用 domain randomization
```

---

### 33.4 `policy_obs_key` / `value_obs_key` 决定 privileged_state 是否使用

`joystick.py` 构造了：

```text id="j13r4r"
obs["state"]
obs["privileged_state"]
```

但本脚本通过 PPO network config 决定 actor/critic 使用哪个 key。

如果最终配置是：

```text id="pv2g46"
policy_obs_key = "state"
value_obs_key = "state"
```

那 `privileged_state` 虽然被环境构造了，但 critic 不使用它。

如果最终配置是：

```text id="5zs3wy"
policy_obs_key = "state"
value_obs_key = "privileged_state"
```

才是 privileged critic/asymmetric actor-critic。

所以不要看到环境有 `privileged_state` 就直接认为训练用了 privileged learning。

---

### 33.5 `play_only` 不是简单跳过训练函数

`play_only` 做的是：

```text id="pd7xhx"
ppo_params.num_timesteps = 0
```

后面仍然调用：

```text id="aznmv1"
train_fn(...)
```

所以它更像是“通过 Brax train 加载/构造 params 后直接推理”，不是完全绕开训练流程。

建议使用 `--play_only` 时同时提供：

```bash id="zmtzrq"
--load_checkpoint_path=...
```

否则行为可能不符合“播放已训练模型”的直觉。

---

### 33.6 checkpoint 目录解析假设子目录名是数字

如果传入的是目录：

```python id="cpq5kz"
latest_ckpts.sort(key=lambda x: int(x.name))
```

所以 checkpoint 子目录必须能转成整数，例如：

```text id="a2jz9u"
0
1000000
2000000
```

如果目录里有：

```text id="k6rsgl"
config
latest
backup
```

会报错。

---

### 33.7 保存 config 不一定完整覆盖所有实验信息

脚本保存：

```text id="umlyfi"
env_cfg.to_dict()
```

但没有明确保存：

```text id="wh2spw"
ppo_params 完整内容
env_cfg_overrides 独立内容
命令行 flags
domain_randomization 是否开启
policy/value obs key 最终值
```

虽然部分信息会打印到 stdout，也可能进入 WandB/TB，但从源码看，checkpoint 目录中明确写入的 JSON 只有 env config。

---

### 33.8 eval_env / infer_env 是重新创建的环境

训练、评估、推理不是同一个 env 对象：

```text id="pcc3wp"
env
eval_env
infer_env
```

这通常没问题，但意味着：

```text id="qgokbg"
如果某些状态只存在于 env 实例中，不会自动复制到 eval_env/infer_env。
```

当前代码通过 registry 和 config 重新创建环境，所以应当关注 config 是否一致。

---

### 33.9 inference rollout 不传 randomization_fn

训练时如果启用：

```text id="vk1dpv"
--domain_randomization
```

则 train_fn 有 randomization_fn。

但视频推理时：

```python id="vg8t1k"
wrapped_infer_env = wrapper.wrap_for_brax_training(
    infer_env,
    episode_length=...,
    action_repeat=...,
)
```

没有传 `randomization_fn`。

所以视频表现是在非随机化 inference 环境中生成的。

---

### 33.10 vision 支持需要进一步确认

脚本里有 vision 分支：

```text id="z2xweh"
ppo_networks_vision
env_cfg_overrides["vision"] = True
vision_config.nworld
```

但当前已读的 G1 `joystick.py` 没看到 vision observation 构造。要确认 vision 是否真的能跑，必须看：

```text id="mf94wj"
wrapper.py
其他 vision 相关代码
env config 是否支持 vision_config
```

不能仅凭这个训练脚本断言当前 G1 pipeline 已完整支持视觉输入。

【35. 当前文件在整个 pipeline 中的定位总结】

一句话总结：

```text id="n36185"
train_jax_ppo.py 是 G1 JAX/Brax PPO 训练 pipeline 的总入口；它不实现环境和算法细节，但负责把环境、配置、wrapper、Brax PPO、日志、checkpoint、评估、推理和视频录制串起来。
```

最关键的数据流是：

```text id="iqzcxg"
env_name
→ registry.get_default_config
→ registry.load
→ Joystick/G1Env/MjxEnv
→ wrapper.wrap_for_brax_training
→ brax PPO train
→ make_inference_fn + params
→ deterministic rollout
→ render video
```

你读后续代码时需要记住这些变量/函数：

```text id="x4m3zd"
_ENV_NAME
_IMPL
_PLAYGROUND_CONFIG_OVERRIDES
_DOMAIN_RANDOMIZATION
_POLICY_OBS_KEY
_VALUE_OBS_KEY
get_rl_config
env_cfg
ppo_params
env_cfg_overrides
training_params
network_factory
train_fn
wrapper.wrap_for_brax_training
registry.get_domain_randomizer
make_inference_fn
wrapped_infer_env
do_rollout
```

当前文件是训练 pipeline 的关键节点。前面读的 `registry.py / locomotion.__init__.py / joystick.py / base.py / mjx_env.py / g1_constants.py` 解决的是“环境怎么定义和运行”；这个文件解决的是“这个环境如何被 Brax PPO 真正训练、评估、保存和渲染”。
